Open Source — aws-cdk

PR #38533 ↗

the problem

When an ECS EC2 service uses a CodeDeploy deployment controller, changes to capacityProviderStrategies on the underlying CloudFormation resource don't natively trigger an environment refresh — CodeDeploy relies on deployment group hooks rather than standard resource-state updates, so updates to instance architecture or allocation weights silently fail to apply.

what i built

A deterministic helper, hashCapacityProviderStrategies, that computes a stable hash signature of the active strategy configuration, plus an evaluation check in the Ec2Service construct that detects a CodeDeploy setup and applies a DeploymentConfiguration.TriggerHash override on the underlying CfnService — forcing CloudFormation to register the mutation and correctly kick off the CodeDeploy lifecycle.

status

Open PR against aws/aws-cdk, currently pending maintainer review — closes a tracked bug report and ships with a dedicated unit test.

  • TypeScript
  • AWS CDK
  • ECS
  • CodeDeploy
  • CloudFormation
